Abstract

In-hand reorientation enables robots to place an object in the target pose required by downstream tasks. Existing proprioceptive approaches have demonstrated goal-conditioned reorientation, but following continuous-valued commands precisely without external object-pose sensing remains challenging. We present DexOrient, a proprioception-only framework for precise, command-guided reorientation of objects in hand. An object property adapter (OPA) infers a latent representation of object properties, while a rotation progress estimator (RPE) predicts per-step angular increments that are accumulated into rotation progress. A policy trained in simulation uses both estimates to rotate the object and stabilize it at the commanded angle. The RPE is fine-tuned on real-robot trajectories collected from its own closed-loop rollouts, reducing the bias in tracking rotation progress.

On the LEAP Hand, DexOrient achieves 81.0% success within a 20° tolerance for commands from 22.5° to 180°, up from 57.5% before fine-tuning. In comparison, an RMA-style baseline that jointly encodes object properties and rotation progress in a single latent achieves a lower success rate of 44.0%. Qualitative demonstrations include unseen objects, mid-command mass changes, and external disturbances.

How DexOrient Works

1

Base Policy Training (Sec. III-B)

We train the base policy π jointly with a privileged encoder G in simulation using PPO.

Observations and Actions. The base policy observation is defined as

ot = [xt−2:t, zt, θcmd, φt] ∈ ℝ106,

where zt = G(pt) ∈ ℝ8 is the object property latent. Action at ∈ [−1, 1]16 updates the joint targets as qtart+1 = qtart + αat, where α is the action scale. A low-level PD controller converts the resulting target positions into motor torques.

Privileged Encoder. The privileged vector pt ∈ ℝ9 contains the object position, scale, mass, fingertip friction coefficient, and center-of-mass offset. We keep φt out of pt and feed it to the policy as a separate input, so zt does not need to encode rotation progress (Sec. III-E). The policy and value function share an MLP, and the encoder G is trained end-to-end with them through the reinforcement learning objective.

Reward Function. The reward combines task terms with a regularizer. The task terms drive the object toward the commanded angle and encourage a static grasp once the target is reached,

r = λprogrprog + λnearrnear + λposrpos + λstillrstill + λsuccrsucc − rpen,

where each λ is a non-negative weight. Let et = θcmd − φt. The progress reward term rprog = |et−1| − |et| encourages error reduction within the current command and penalizes motion that increases error, and a proximity reward term rnear = exp(−|et| / σe) encourages accurate convergence to the target, with decay scale σe. To encourage the object to remain within the palm, we add the position term rpos = exp(−dt / σd), where dt is the Euclidean distance from the object center to its canonical in-hand location.

In addition, to make the object settle, we define the on-target indicator 𝕀t = 1[|et| ≤ εθ ∧ dt ≤ εd] with tolerances εθ and εd, and the stillness term rstill = 𝕀t exp(−‖ωt‖2 − κ‖q̇t‖2), where ωt is the object angular velocity, q̇t is the joint velocity, and κ balances the two. A success bonus rsucc = 1 is given once 𝕀t = 1 holds for Nh consecutive steps.

The regularizer rpen penalizes action magnitude, object displacement from the canonical in-hand location, deviation from the initial grasp pose, and object falling.

2

Object Property Adapter (Sec. III-C)

The privileged latent zt is unavailable on hardware. As shown in Fig. 2(c), the OPA infers it from a window of 30 recent proprioceptive frames as ẑt = A(xt−29:t). The quantities in pt stay nearly constant within an episode, so a bounded window carries enough evidence to identify them. We therefore implement A as a stateless temporal convolutional network. With π and G frozen, A is trained to regress the privileged latent with MSE loss,

ℒOPA = ‖ẑt − zt‖22.

The target zt = G(pt) comes from the privileged encoder trained in Sec. III-B.

3

Rotation Progress Estimator (Sec. III-D)

Incremental Estimation. The rotation progress φt accumulates from command start time t0 and is not uniquely mapped to some fixed-length proprioception frame history. We therefore estimate local angle increments and accumulate them explicitly,

Δψ̂t = R(xt−7:t),    φ̂t = φ̂t−1 + Δψ̂t,

with φ̂t0 = 0 at every command boundary. R is a GRU followed by a linear head. It encodes each window from a zero hidden state and carries no state across steps.

Drift-Aware Loss. We supervise both local prediction accuracy and accumulated drift. For K consecutive steps within a command, let εt = Δψ̂t − Δψt. We minimize

ℒRPE = (λs/K) ∑k=0K−1 εt+k2 + (λi/K) ∑k=0K−1 (∑j=0k εt+j)2,

where the first term penalizes per-step error and the second penalizes accumulated drift, and λs and λi balance the two.

Training and Fine-Tuning. As shown in Fig. 2(d), we train the RPE on real-robot data. Let 𝒟(s) denote hardware trajectories collected with the frozen π and OPA while the progress source s drives the policy. All trajectories are labeled by the overhead camera (Sec. IV-A). We first collect 𝒟0 = 𝒟(cam) with camera-measured progress in the loop and pretrain an initial estimator R0 on it. Once R0 drives the policy, its errors change the trajectories, which then leave the distribution of 𝒟0. We therefore collect 𝒟n = 𝒟(Rn−1) and refine the estimator in a DAgger-style manner,

Rn = FTR0(𝒟1:n ∪ 𝒟0),    n ≥ 1,

where the offline fine-tuning operator FTR0(·) minimizes ℒRPE on the given data from the initialization R0. Sec. IV-C compares the initial estimator R0 and fine-tuned estimators R1 and R2 in both open-loop estimation error and closed-loop success.

Implementation Details (Sec. IV-A)

Simulation setup. We train the base policy in Isaac Lab on a cylinder with a diameter and height of 7.5 cm. Each episode has a 40 s horizon and starts from a canonical grasp and object position. During base policy and OPA training, we scale the cylinder by a factor from {0.9, 0.95, 1.0, 1.05, 1.1}. We also randomize the object mass (0.10–0.45 kg), center-of-mass offset (±1 cm per axis), fingertip friction coefficient (0.6–1.3), joint stiffness (0.7–2.0), and joint damping (0.025–0.070). After each success, we sample a new command and reset the rotation progress to zero. An episode terminates early if the object drops or tilts excessively. The policy runs at 20 Hz in simulation and on hardware.

Hardware setup. All real-world experiments use a 16-DoF LEAP Hand with the palm facing up (Fig. 1(a)). Quantitative trials use 3D-printed cylinders with diameters of 6.5–9 cm, heights of 6, 7, or 8 cm, and masses of 60–100 g, partly outside the simulated range. The everyday objects in Fig. 5(a) are unseen during training. A RealSense camera observes a dark arrow marker on the top surface of the object. We extract the arrow contour by grayscale thresholding and take its principal axis as the object yaw. These measurements label the data for training the rotation progress estimator and provide ground truth for evaluation. Dataset 𝒟0 contains 400 commands, and each fine-tuning round collects 200 more with the previous estimator in the loop.

Evaluation metrics. Target rotation commands are uniformly sampled as θcmd ∼ 𝒰[22.5°, 180°]. In simulation, each command is given an execution budget of 200 steps, where the explicit student obtains progress from R1. On hardware, we set this budget to 150 steps. We define the achieved angle of a command, θach, as the mean of φt over the longest interval with maxt φt − mint φt ≤ 20° in the last 50 control steps of an episode. If the interval length is less than 10 control steps, θach is undefined. A trial succeeds if |θach − θcmd| ≤ θe. Trials with undefined θach count as failure. Table I reports success rates at θe ∈ {10°, 15°, 20°}, the median terminal error, and the slope, intercept, and R2 of a least-squares fit of θach on θcmd. Training uses a tighter angular tolerance εθ for success. Table II lists it with the other training constants of Sec. III. We also report the progress estimation error |φ̂t − φt| against the camera in Fig. 3(c) and (d), computed offline by replaying each estimator on recorded hardware trials.

Timer baseline. An intuitive strategy to reach a commanded angle is to rotate the object continuously and stop when a timer-based model predicts arrival. We build this Timer baseline from established recipes. Its continuous-rotation policy follows the two-stage RMA training of HORA. It uses the environment and reward of the official LEAP Hand Isaac Lab release. The policy never observes the command. From 236 hardware trials, we fit a quadratic map from angle to the median steps needed to reach it. Inverting the map gives its progress estimate at every step. The motion stops once the predicted steps for θcmd have elapsed. This map is calibrated for the continuous-rotation policy, whereas DexOrient moves differently for each command. We therefore evaluate each estimator on trajectories of the policy it is deployed with.

Command Tracking Performance (Sec. IV-B)

We first analyze command-tracking performance by separating the base manipulation policy from the RPE. In the vision oracle of Fig. 3(a), the same base policy and OPA are deployed unchanged, but the overhead camera supplies φ̂t in place of the RPE. Success reaches 100%, so the base policy and the OPA complete the command-following task whenever progress is accurate. Fig. 3(b) replaces the camera with the RPE, which gives the fully proprioceptive system. It succeeds on 81.0% of N = 200 commands under the criterion in Sec. IV-A. Table I lists the full metrics of both systems.

The remaining gap therefore lies in progress estimation. Fig. 3(c) compares the open-loop error of the RPE with that of the Timer baseline. The Timer error does not converge. Its median rises from about 15° after 20 control steps to over 40° near the end, and stays above the RPE error throughout the command. This error comes from trial-to-trial variation in rotation speed, which time alone cannot capture. For instance, the continuous-rotation policy takes between 98 and 195 control steps to rotate the object by 180° in most trials, so no single time-to-angle map fits them all. The RPE error instead settles at about 10° after an initial rise. Proprioception thus captures the trial-specific rotation that time alone misses.

On-Policy Fine-Tuning of the RPE (Sec. IV-C)

We compare three RPE checkpoints: initial estimator R0, R1 = FTR0(𝒟1 ∪ 𝒟0), and R2 = FTR0(𝒟1:2 ∪ 𝒟0). Fig. 3(d) replays all three open-loop on a held-out session that none of them was trained on. Deployed in the loop, the oracle-driven estimator R0 shows a systematic, angle-dependent bias. Its estimate runs ahead of the camera for small commands and falls behind for large ones. The object therefore stops short of small targets and rotates past large ones, which yields a fitted slope of 1.25 and only 57.5% success (Table I). Such a consistent bias indicates that oracle-driven data do not cover the trajectories the RPE induces once it drives the policy, a problem also noted by Röstel et al.

One round of on-policy fine-tuning reduces this bias. R1 lowers the early error peak from 14.0° to 9.4° and the plateau by about 2°. In closed loop, success rises to 81.0%, and both the median terminal error and the mean estimation error are roughly halved.

R2 raises closed-loop success to 85.0%, but the estimator itself does not improve further. Its open-loop curve nearly coincides with that of R1 (Fig. 3(d)), and its mean estimation and median terminal errors are slightly higher. Its intercept also grows from 4.3° to 12.1°, so R2 trades part of the scatter for a positive offset. Since each round takes about two hours of hardware collection and retraining, we deploy R1 in all experiments.

Decoupling Rotation Progress from Object Properties

RMA-style distillation places every unobserved quantity in the privileged vector and recovers all of them with a single adaptation module. Goal-conditioned reorientation needs φt to decide when to stop. A direct extension of this recipe appends φt to pt, which results in an architecture that implicitly encodes the rotation progress. We argue that our architecture shown in Fig. 2(a), which estimates rotation progress and supplies it explicitly to the base policy, performs better than the implicit variant.

To formulate this, we compare an implicit (I) and an explicit (E) encoding of rotation progress,

zIt = GI([pt, φt]),    oIt = [xt−2:t, zIt, θcmd],
zEt = GE(pt),    oEt = [xt−2:t, zEt, θcmd, φt].

A separate base policy is trained for each encoding using the same PPO training procedure. To make the model capacity comparable for the two architectures, the implicit adapter uses the same GRU backbone as the explicit RPE, with a linear head predicting zIt. It is trained with the latent reconstruction loss ℒOPA. The explicit architecture retains the temporal convolutional OPA.

We use the normalized mean-squared error (NMSE) during validation to assess the performance, where

NMSEa = ∑i∈𝒱 ‖ẑai − zai‖22 ⁄ ∑i∈𝒱 ‖zai − z̄a𝒞‖22,

and z̄a𝒞 is the mean privileged latent on a separate calibration set 𝒞. A constant predictor that always outputs z̄a𝒞 has an NMSE of exactly one. Sec. IV-D compares both encodings in task performance and NMSE.

Implicit vs. Explicit Progress Encoding (Sec. IV-D)

In this section, we evaluate both encodings of Sec. III-E. The two privileged teachers perform comparably, both exceeding 99.5% at 20° tolerance in simulation (Table I). A performance gap emerges when privileged inputs are replaced with learned estimates. Within 20°, the explicit student reaches 93.2% in simulation and 81.0% on hardware, whereas the implicit student reaches 78.2% and 44.0%, respectively. On hardware, the implicit student's achieved angle is also less closely related to the commanded angle, with a regression R2 of 0.28 compared with 0.89 for the explicit student.

To investigate representation differences associated with this performance gap, we evaluate the adapted latents on a common test set. In the implicit encoding, object scales overlap (Fig. 4(a)), while the same points colored by φt show a clear gradient (Fig. 4(c)). The implicit latent is thus organized mainly by progress. The explicit encoding instead orders the scales along a clear trend (Fig. 4(b)). The NMSE in Fig. 4(d) agrees with this picture. Over three seeds, the explicit adapter reaches 0.547 ± 0.047. The implicit adapter stays near the mean-predictor level throughout training and ends above it at 1.223 ± 0.320, so it recovers no more than a constant average latent would.

These results support keeping φt out of the privileged latent. A bounded proprioceptive window can provide evidence about object properties and the current interaction state. In contrast, history-dependent quantities like rotation progress accumulate from the command boundary and are generally not uniquely determined by recent observations alone. When one latent must hold both, progress dominates its structure at the expense of object information. Separate modules avoid this conflict. This suggests that quantities accumulated over a command may be better estimated by a dedicated module than folded into the latent of a windowed adapter.

Qualitative Evaluation on Generalization and Robustness (Sec. IV-E)

Beyond the quantitative analysis discussed above, we further evaluate the capability of our deployed system in three broader settings. The first condition substitutes everyday objects for the training cylinder (Fig. 5(a)). These objects differ from the training cylinder in geometry, surface texture, and mass distribution, and none was used in simulation training. The second changes the object's mass during a command. Water is poured into a container while the hand is rotating it (Fig. 5(b)), so the dynamics the policy is adapting to shift mid-trajectory rather than being fixed at episode start. The third applies an external disturbance, manually tilting the object away from the palm center while a command is in progress (Fig. 5(c)). In each case, the hand completes the rotation and stabilizes the object without dropping the object.

Several training components partially explain DexOrient's generalization and robustness. Domain randomization over object scale, friction, and center-of-mass offset exposes the policy to object variations beyond the training cylinder. Mass randomization prepares it for heavier or lighter objects. Because the OPA re-estimates object properties from a sliding window, it can track a mass change mid-command rather than only at episode start. The reward term that pulls the object toward its canonical pose encourages recovery from tilting. The contribution of each component remains to be isolated.
